Transformer Architecture

1. High-Level View

A Transformer block alternates between:

  1. Token mixing via attention
  2. Feature mixing via the MLP

For hidden states

\[ X \in \mathbb{R}^{B \times T \times d_{\text{model}}}, \]

a modern pre-norm Transformer block is roughly

\[ X' = X + \operatorname{Attention}(\operatorname{Norm}(X)) \]

\[ X_{\text{out}} = X' + \operatorname{MLP}(\operatorname{Norm}(X')). \]

NoteCore intuition
  • Attention mixes information across tokens.
  • The MLP mixes information across features within each token.
  • Residual connections preserve and incrementally update the residual stream.

3. Normalization

LayerNorm

\[ \operatorname{LN}(x) = \gamma \frac{x-\mu}{\sqrt{\sigma^2+\epsilon}} + \beta. \]

RMSNorm

\[ \operatorname{RMSNorm}(x) = \gamma \frac{x} {\sqrt{\frac{1}{d}\sum_i x_i^2+\epsilon}}. \]

Pre-Norm vs Post-Norm

Post-norm

\[ X_{l+1} = \operatorname{Norm} \left( X_l + F(X_l) \right) \]

Pre-norm

\[ X_{l+1} = X_l + F(\operatorname{Norm}(X_l)). \]

5. Feed-Forward Network

The MLP operates independently on each token.

Classic Transformer FFN:

\[ \operatorname{FFN}(x) = W_2 \sigma(W_1x). \]

Typical dimensions:

\[ d_{\text{model}} \rightarrow d_{\text{ff}} \rightarrow d_{\text{model}}. \]

Usually

\[ d_{\text{ff}} > d_{\text{model}}. \]

SwiGLU

Modern LLMs often use gated MLPs:

\[ \operatorname{SwiGLU}(x) = W_o \left[ \operatorname{SiLU}(W_gx) \odot (W_ux) \right]. \]

For the gating intuition, parameter-count derivation, model-width comparisons, and GPT-OSS variant, see Gated Activations.

NoteAttention vs MLP

Attention:

\[ [B,T,d] \rightarrow \text{mix across } T \]

MLP:

\[ [B,T,d] \rightarrow \text{mix across } d \]

This is a useful way to think about a Transformer as alternating token mixing and feature mixing.

6. Full Decoder-Only Transformer

Pipeline:

\[ \text{tokens} \rightarrow \text{embeddings} \rightarrow L \times \text{Transformer blocks} \rightarrow \text{final norm} \rightarrow \text{LM head} \rightarrow \text{logits}. \]

For vocabulary size \(V\),

\[ X_L \in \mathbb{R}^{B\times T\times d} \]

and

\[ \text{logits} = X_L W_{\text{vocab}} \in \mathbb{R}^{B\times T\times V}. \]

Minimal PyTorch implementation

This is a small, readable decoder-only Transformer rather than a production-optimized implementation. It uses:

  • pre-norm residual blocks
  • causal multi-head self-attention
  • RMSNorm
  • a SwiGLU MLP
  • learned absolute position embeddings
  • a weight-tied language-model head
import torch
import torch.nn as nn
import torch.nn.functional as F


class RMSNorm(nn.Module):
    def __init__(self, d_model, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d_model))

    def forward(self, x):
        # Compute the normalization statistic in FP32 for stability.
        rms = x.float().pow(2).mean(dim=-1, keepdim=True)
        normalized = x.float() * torch.rsqrt(rms + self.eps)
        return (normalized * self.weight.float()).to(x.dtype)


class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, num_heads, dropout=0.0):
        super().__init__()
        assert d_model % num_heads == 0

        self.num_heads = num_heads
        self.d_head = d_model // num_heads
        self.dropout = dropout
        self.qkv_proj = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x):
        batch_size, seq_len, d_model = x.shape
        q, k, v = self.qkv_proj(x).chunk(3, dim=-1)

        def split_heads(tensor):
            return tensor.view(
                batch_size, seq_len, self.num_heads, self.d_head
            ).transpose(1, 2)

        q, k, v = map(split_heads, (q, k, v))

        # PyTorch chooses an available SDPA kernel and applies the causal mask.
        output = F.scaled_dot_product_attention(
            q,
            k,
            v,
            dropout_p=self.dropout if self.training else 0.0,
            is_causal=True,
        )

        output = output.transpose(1, 2).contiguous().view(
            batch_size, seq_len, d_model
        )
        return self.out_proj(output)


class SwiGLU(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.gate_proj = nn.Linear(d_model, d_ff, bias=False)
        self.up_proj = nn.Linear(d_model, d_ff, bias=False)
        self.down_proj = nn.Linear(d_ff, d_model, bias=False)

    def forward(self, x):
        return self.down_proj(F.silu(self.gate_proj(x)) * self.up_proj(x))


class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout=0.0):
        super().__init__()
        self.attn_norm = RMSNorm(d_model)
        self.attention = CausalSelfAttention(d_model, num_heads, dropout)
        self.mlp_norm = RMSNorm(d_model)
        self.mlp = SwiGLU(d_model, d_ff)
        self.residual_dropout = nn.Dropout(dropout)

    def forward(self, x):
        x = x + self.residual_dropout(self.attention(self.attn_norm(x)))
        x = x + self.residual_dropout(self.mlp(self.mlp_norm(x)))
        return x


class DecoderOnlyTransformer(nn.Module):
    def __init__(
        self,
        vocab_size,
        max_seq_len,
        d_model,
        num_heads,
        num_layers,
        d_ff,
        dropout=0.0,
    ):
        super().__init__()
        self.max_seq_len = max_seq_len
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.position_embedding = nn.Embedding(max_seq_len, d_model)
        self.embedding_dropout = nn.Dropout(dropout)
        self.blocks = nn.ModuleList(
            [
                TransformerBlock(d_model, num_heads, d_ff, dropout)
                for _ in range(num_layers)
            ]
        )
        self.final_norm = RMSNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)

        # The input embedding and output classifier share one weight matrix.
        self.lm_head.weight = self.token_embedding.weight

    def forward(self, token_ids):
        _, seq_len = token_ids.shape
        if seq_len > self.max_seq_len:
            raise ValueError(
                f"sequence length {seq_len} exceeds {self.max_seq_len}"
            )

        positions = torch.arange(seq_len, device=token_ids.device)
        x = self.token_embedding(token_ids)
        x = x + self.position_embedding(positions)[None, :, :]
        x = self.embedding_dropout(x)

        for block in self.blocks:
            x = block(x)

        return self.lm_head(self.final_norm(x))
torch.manual_seed(0)

model = DecoderOnlyTransformer(
    vocab_size=100,
    max_seq_len=32,
    d_model=64,
    num_heads=4,
    num_layers=2,
    d_ff=128,
)

9. Modern LLM Block

The original 2017 Transformer used post-norm blocks, LayerNorm, sinusoidal positions, dense feed-forward layers, and standard multi-head attention. Modern LLMs retain the residual attention-plus-MLP skeleton, but change nearly every component around it for training stability and inference efficiency.

Major architectural changes

Change Replaces Why it is used
Pre-norm + RMSNorm post-norm + LayerNorm more stable gradient flow at large depth; cheaper normalization
SwiGLU / gated MLP ReLU FFN improves the expressiveness and quality of the token-wise MLP
RoPE additive sinusoidal positions injects relative-position structure directly into Q and K
GQA or MQA one KV head per query head reduces KV-cache size and decode-time memory bandwidth
MLA directly cached per-head K/V compresses attention state into a lower-dimensional latent cache
Sparse MoE FFN one dense FFN for every token increases total parameter capacity without activating all parameters per token
Local/global attention patterns full attention in every layer reduces long-context attention cost while retaining occasional global communication
QK-Norm and logit control unconstrained Q/K scale prevents attention logits from becoming unstable as models scale
Multi-token prediction next-token-only training head adds training signals for several future tokens and can support faster decoding

These are a menu, not a single standard block. Different model families choose different combinations.

Representative model families

The entries below refer to specific publicly documented generations; a family name alone is not a stable architectural specification.

Family / example Dense or MoE? Attention and position FFN / other distinguishing choices
Llama 3 / 3.1 Dense GQA, RoPE, full causal attention pre-norm RMSNorm and SwiGLU; a useful modern dense baseline
Qwen3 Dense and sparse-MoE variants GQA, RoPE, and QK-Norm; removes the earlier QKV biases SwiGLU; MoE variants route each token to a subset of fine-grained experts; one model can be post-trained for thinking and non-thinking modes
DeepSeek-V3 / R1 DeepSeekMoE MLA replaces a conventional per-head KV cache with compressed latent state; RoPE is applied to a decoupled positional component fine-grained routed experts plus shared experts, auxiliary-loss-free load balancing, and a multi-token-prediction training objective; R1 changes post-training rather than the V3 base architecture
Kimi K2 Ultra-sparse MoE MLA for KV-cache efficiency about 1T total parameters but 32B active per token; MuonClip is a notable optimizer/training change, not a block component
GPT-OSS 120B / 20B Sparse MoE alternating full-context and sliding-window causal attention, GQA, RoPE, and learned attention sinks four routed experts active per token; MoE weights are distributed in MXFP4; 120B has 117B total but 5.1B active parameters

Dense FFN versus sparse MoE

In a dense Transformer, every token passes through the same FFN:

\[ y = \operatorname{FFN}(x). \]

In a sparse mixture-of-experts layer, a router selects a small subset of \(E\) experts:

\[ y = \sum_{e \in \operatorname{TopK}(r(x))} g_e(x)\operatorname{FFN}_e(x). \]

This separates:

  • total parameters, which determine model capacity and memory footprint, from
  • active parameters per token, which more closely determine per-token FFN compute.

MoE does not make scaling free. It introduces routing, expert load balancing, all-to-all communication, and a large weight-memory footprint.

Attention evolution

MHA
 ├── GQA / MQA: share K and V across query heads
 ├── MLA: cache a compressed latent representation
 └── local/global patterns: change which token pairs interact

These address different bottlenecks:

  • GQA/MQA primarily shrink the KV cache.
  • MLA learns a low-rank compression of the cached attention state.
  • Sliding-window attention reduces the number of attended positions.
  • QK-Norm and attention-logit soft caps target numerical stability.
  • Attention sinks provide learned positions that all tokens can attend to, helping stabilize windowed or streaming attention.

Architecture versus training and systems

Several important “modern LLM” advances do not change the basic Transformer block:

Category Examples
Training objective multi-token prediction, instruction tuning, preference optimization, reasoning RL
Optimizer / precision MuonClip, FP8 training, MXFP4 weight storage
Attention kernel FlashAttention
Inference state KV caching, paged attention, prefix caching
Decoding speculative decoding, constrained decoding, reasoning budgets
Product system model routing, tools, retrieval, memory, multimodal encoders

For example, DeepSeek-R1 largely inherits the DeepSeek-V3 model architecture and changes the post-training recipe. Similarly, ChatGPT capabilities cannot be read as direct evidence of a particular attention or MoE design because the product includes models and system-level components whose block-level details are not publicly specified.
